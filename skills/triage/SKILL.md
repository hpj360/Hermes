# Triage

Move issues on the project issue tracker through a small state machine of triage roles.

适配自 mattpocock/skills (MIT-style, 保留原始方法论，适配 Hermes 编排框架)。

## 角色状态机

两个 **category** 角色：
- `bug` — something is broken
- `enhancement` — new feature or improvement

五个 **state** 角色：
- `needs-triage` — maintainer needs to evaluate
- `needs-info` — waiting on reporter for more information
- `ready-for-agent` — fully specified, ready for an AFK agent
- `ready-for-human` — needs human implementation
- `wontfix` — will not be actioned

每个 triaged issue 应携带恰好一个 category role + 一个 state role。

## 在 Hermes 中的编排

本 skill 作为 `issue-triage` loop pattern 的 sub-agent 内容来源：

| Loop sub_agent | Triage 角色 | 职责 |
|----------------|------------|------|
| issue_scanner | needs-triage | 扫描 unlabeled/needs-triage issue |
| duplicate_detector | (并行) | 检测疑似重复 issue |
| label_suggester | (并行) | 推荐 category + priority 标签 |

## Process

### 1. Gather context
Read the full issue (body, comments, labels, author, dates). Parse prior triage notes. Explore codebase using domain glossary. Run two checks:
- **redundancy**: search for existing implementation by domain concept
- **prior rejection**: read `.out-of-scope/*.md` for similar rejected requests

### 2. Recommend
Tell maintainer your category + state recommendation with reasoning. Wait for direction.

### 3. Verify the claim
- For a bug: reproduce from reporter's steps
- For a PR: confirm the diff does what it claims

### 4. Grill (if needed)
If request needs fleshing out, use grilling + domain-modeling to sharpen it.

### 5. Apply the outcome
- `ready-for-agent` — post an agent brief comment
- `ready-for-human` — note why it can't be delegated
- `needs-info` — post triage notes template
- `wontfix` — close with explanation (already-implemented / rejected)
- `needs-triage` — apply the role

## Completion criteria
- [ ] Every triaged issue carries exactly one category + one state role
- [ ] AI-generated comments start with `> *This was generated by AI during triage.*`
- [ ] Redundancy check performed and documented
- [ ] Prior rejection check performed and documented
